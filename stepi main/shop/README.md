# STEP Store — ონლაინ მაღაზია

საკურსო პროექტი 1 (HTML / CSS / JS) — ონლაინ მაღაზია საკუთარი ბექენდითა და
**SQLite** ბაზით. მომხმარებელი რეგისტრირდება, გადის ავტორიზაციას, ათვალიერებს
და ფილტრავს ნივთებს, ავსებს კალათას, აფორმებს შეკვეთას და წერს შეფასებებს.

---

## 1. გაშვება

ბექენდი ორ ვარიანტშია დაწერილი — **Python** და **Node.js**. ორივე ერთსა და იმავეს
აკეთებს, ერთსა და იმავე ბაზას (`server/shop.db`) იყენებს და ერთი და იგივე API-ს
გასცემს. აირჩიე ერთი.

### ვარიანტი A — Python (რეკომენდებული)

საჭიროა **Python 3.9+**. `sqlite3` სტანდარტულად მოყვება, ამიტომ `pip install`
არაფერი არ არის საჭირო.

```bash
python server/server.py
```

> Windows-ზე, თუ `python` არ მუშაობს, სცადე `py server/server.py`

### ვარიანტი B — Node.js

საჭიროა **Node.js 22.5+** (ჩაშენებული `node:sqlite`-ის გამო).

```bash
node server/server.js
```

ორივე შემთხვევაში გაიხსნება: **http://localhost:3000**
ბაზა `server/shop.db` პირველივე გაშვებაზე ავტომატურად იქმნება და ივსება.
გასაჩერებლად — `Ctrl+C`.

> **ბაზის განულება:** წაშალე `server/shop.db` და ხელახლა გაუშვი სერვერი.

### სერვერის გარეშე

თუ `index.html`-ს უბრალოდ ბრაუზერში გახსნი (ან Live Server-ით გაუშვებ), საიტი
მაინც იმუშავებს: სერვერთან კავშირის ვერ დამყარებისას ავტომატურად ირთვება
ლოკალური სარეზერვო კატალოგი (`js/local-products.js`) და გამოჩნდება შეტყობინება.
ამ რეჟიმში კალათა `localStorage`-ში ინახება და ავტორიზაცია არ მოქმედებს.

## 3. ბექენდი და ბაზა

Python-ის ვერსია დაწერილია `http.server` და `sqlite3` მოდულებით, Node-ისა —
ჩაშენებული `http`-ითა და `node:sqlite`-ით. ორივეში ერთი და იგივე სერვერი გასცემს
როგორც API-ს, ისე საიტის ფაილებს, ამიტომ CORS-ის პრობლემა საერთოდ არ დგება.
პაროლის ჰეშირებაც ერთნაირია (scrypt, იგივე პარამეტრებით), ასე რომ ერთ ვერსიაში
შექმნილი ანგარიშით მეორეშიც შეძლებ შესვლას.

### Python-ის ვერსიის სტრუქტურა

კოდი სამ ფენად არის დაყოფილი:

| ფაილი | პასუხისმგებლობა |
|---|---|
| `db.py` | კავშირი ბაზასთან, სქემა (`CREATE TABLE`), seed, პაროლის ჰეშირება |
| `models.py` | მოდელები — თითო კლასი თითო ცხრილზე; **მთელი SQL აქ წერია** |
| `server.py` | HTTP: მარშრუტები, ავტორიზაციის შემოწმება, სტატიკური ფაილები |

`models.py`-ის კლასები: `Category`, `Product`, `User`, `Session`, `Cart`,
`Rating`, `Order`. მაგალითად:

```python
Product.search(conn, {"brand": "AMD", "sort_by": "price"})
Cart.set_item(conn, user_id, "r7-7800x3d", 2)
Rating.upsert(conn, product_id, user, 5, "ძალიან კარგია")
Order.create_from_cart(conn, user_id, payload)
```

`server.py` მხოლოდ ამ მეთოდებს იძახებს და თავად SQL-ს არ წერს — ასე ლოგიკა
ერთ ადგილას რჩება და მარშრუტები მოკლე და წასაკითხია.

### ბაზის სქემა

| ცხრილი | დანიშნულება |
|---|---|
| `categories` | კატეგორიები (პროცესორები, ვიდეოდაფები) |
| `products` | ნივთები: ფასი, ფასდაკლებამდე ფასი, მარაგი, ბრენდი, სურათები |
| `users` | მომხმარებლები; პაროლი ინახება **scrypt**-ჰეშად, ცალკე მარილით (salt) |
| `sessions` | აქტიური ტოკენები |
| `carts` / `cart_items` | კალათა და მასში არსებული ნივთები |
| `ratings` | შეფასებები: ვარსკვლავები **და** ტექსტი (`UNIQUE(product_id, user_id)`) |
| `orders` / `order_items` | გაფორმებული შეკვეთები |

ნივთის საშუალო რეიტინგი ბაზაში არ ინახება — ის ყოველ მოთხოვნაზე ითვლება
`AVG(value)`-ით, ასე რომ მონაცემები ყოველთვის სინქრონულია.

### API endpoint-ები

| ფუნქცია | მეთოდი | მისამართი |
|---|---|---|
| ყველა ნივთი | GET | `/shop/products/all?page_index=&page_size=` |
| ძიება და ფილტრაცია | GET | `/shop/products/search?keywords=&category_id=&brand=&rating=&price_min=&price_max=&sort_by=&sort_direction=` |
| ერთი ნივთი | GET | `/shop/products/id/{id}` |
| კატეგორიები | GET | `/shop/products/categories` |
| ბრენდები | GET | `/shop/products/brands?category_id=` |
| შეფასება (ვარსკვლავი + ტექსტი) | POST | `/shop/products/rate` 🔒 |
| კალათის ნახვა | GET | `/shop/cart` 🔒 |
| ნივთის დამატება | POST | `/shop/cart/product` 🔒 |
| რაოდენობის შეცვლა | PATCH | `/shop/cart/product` 🔒 |
| ნივთის წაშლა | DELETE | `/shop/cart/product` 🔒 |
| კალათის გასუფთავება | DELETE | `/shop/cart` 🔒 |
| შეკვეთის გაფორმება | POST | `/shop/cart/checkout` 🔒 |
| რეგისტრაცია | POST | `/auth/sign_up` |
| შესვლა | POST | `/auth/sign_in` |
| მიმდინარე მომხმარებელი | GET | `/auth` 🔒 |
| მომხმარებელი ID-ით | GET | `/auth/id/{id}` |

🔒 — საჭიროებს `Authorization: Bearer <token>` სათაურს.

### ავტორიზაცია როგორ მუშაობს

1. რეგისტრაციისას პაროლი იჰეშება `scrypt`-ით შემთხვევითი salt-ით და ბაზაში
   მხოლოდ ჰეში ინახება — ღია პაროლი არსად იწერება.
2. შესვლისას სერვერი ამოწმებს ჰეშს და გასცემს ტოკენს, რომელსაც `sessions`-ში ინახავს.
3. ბრაუზერი ტოკენს `localStorage`-ში ინახავს და ყოველ დაცულ მოთხოვნას
   `Authorization: Bearer <token>` სათაურით აგზავნის (`js/api.js → request()`).
4. გასვლისას ტოკენი იშლება.

## 4. დავალების მოთხოვნები და მათი შესრულება

### მთავარი გვერდი (`index.html`)

| მოთხოვნა | სად არის |
|---|---|
| ყველა ნივთი ბარათების სახით | `catalog.js → productCard()` |
| სურათი, დასახელება, ფასი, რეიტინგი | იგივე ფუნქცია |
| კალათაში დამატების ღილაკი | ბარათის `data-add` ღილაკი |
| ძიება სახელწოდებით | header-ის ფორმა → `keywords` პარამეტრი |
| კალათის აიკონი მრიცხველით | header, `data-cart-count` |
| ფილტრაცია: კატეგორია, ბრენდი, ფასი, რეიტინგი | `aside.sidebar` → `loadFilters()` |
| ნივთზე დაკლიკება → დეტალური გვერდი | `product.html?id=<id>` |
| კალათის აიკონზე დაკლიკება → კალათა | `cart.html` |

დამატებით: გვერდების გადანომვრა, დალაგება, აქტიური ფილტრების „ჩიპები",
ფილტრების URL-ში შენახვა და ბრენდების სიის კატეგორიაზე მორგება.

### ნივთის დეტალური გვერდი (`product.html`)

სურათების გალერეა, ფასი, გამოშვების თარიღი, ბრენდი, მარაგი, ყიდვისა და
კალათაში დამატების ღილაკები და ორი ჩანართი — **Details** და **Review**.
Review-ში ჩანს შემფასებლის სახელი და გვარი + ვარსკვლავები. „შეფასების დატოვება"
ხსნის მოდალურ ფანჯარას: Rating (ვარსკვლავები), ტექსტი და ღილაკი **OK**.

### კალათის გვერდი (`cart.html`)

თითოეული ნივთი ბარათად: სურათი, დასახელება, მარაგი, რეიტინგი, ფასი,
**Reviews** — შეფასებების რაოდენობა, რაოდენობის მომატება–დაკლება და წაშლა.
გვერდით — ავტომატურად დათვლილი ჯამი და „შეკვეთის გაფორმება", რომელიც
შეკვეთას ბაზაში წერს და მარაგს ამცირებს.

## 5. რა შეიძლება დაემატოს

* შეკვეთების ისტორიის გვერდი (`orders` ცხრილი უკვე ივსება);
* ადმინ-პანელი ნივთების დასამატებლად და რედაქტირებისთვის;
* ტოკენის ვადის გასვლა და `refresh_token`-ით განახლება;
* Angular-ზე გადატანა: `api.js` → `ProductService` / `CartService`,
  სამი გვერდი → სამი კომპონენტი, `state` → `BehaviorSubject`.
